# Treader

基于[小纸 Pico 官方固件](https://github.com/MindReset/read_pico_firmware)的分支，把安卓版
[Tomato-Novel](https://github.com/bidabrain/Tomato-Novel) 的核心功能（搜索番茄小说、下载 TXT、检查更新、书城）
、[hupuX](https://github.com/bidabrain/hupuX) 的虎扑浏览，以及经自建 rednote 服务器的小红书浏览做进系统。阅读器、目录、字体、传书沿用官方固件，
在此之上加了书库主页、图片封面、阅读排版、锁屏壁纸、拼音输入、WebDAV 同步和 TF 卡升级。

设计原则：设备是 ESP32-S3 单片机，**能少做就少做**。只有黑白灰界面，没有颜色和主题，没有动画；
图片（封面、壁纸、帖子图）只在需要时解码一次并缓存到 TF 卡。界面风格参考 RickyOS，全部界面和功能说明见
[design/ui.html](design/ui.html)（唯一的设计稿）。联网只在一次操作期间打开，做完就断。

## 其他行为说明

- **联网任务，前台优先**：番茄、书城、虎扑、小红书、WebDAV 共用 `components/tomato` 的一个后台任务，同一时间只做一件事。前台页面发起新请求时，后台在跑的如果是浏览类任务（虎扑、小红书、书城榜单和封面、番茄搜索，不管是哪一页留下的），立即取消让给前台，取消了也不丢已存的缓存；如果是下载或更新番茄书、检查更新、WebDAV 同步，不打断，前台请求排在后面，页面提示“后台正在下载或同步，完成后自动开始”（`tomato_sync_preemptible` / `tomato_sync_preempt`）。每个任务有序号（`tomato_sync_seq`），页面只把自己发起的任务当成自己的。
- **时间**：见下文“时间与时区”。
- **章节数兜底**：检查更新时，服务器扫描结果里没有的书，直接请求
  `https://fanqienovel.com/api/reader/directory/detail?bookId=…`，边下载边数 `"itemId"` 出现次数作为章节数，不解析整个 JSON。
- **阅读中被更新**：正在读的番茄书被后台更新替换后，阅读器保存进度时改用新的文件大小（只追加章节，位置仍有效）。
- **封面**：EPUB 按 OPF 里的 `cover-image` 或 `<meta name="cover">` 找封面，找不到就用文件名带 cover 的图片；
  番茄书在下载时取搜索结果里的 `thumb_url`，存成 `tomato/covers/<文件名>.img`（只收 JPEG/PNG，拿到 WEBP 会去掉图片处理参数再要一次）。
  第一次在书库看到某本书时生成 300×400 灰度缩略图，缓存到 `.treader/covers/`，一本约 120 KB；
  生成期间先显示文字封面，全部生成完整页刷新一次。源文件大小或修改时间变了会重建。锁屏只读缓存，不解码。
  打开书时释放内存里的缩略图（约 1 MB PSRAM）。
- **锁屏壁纸**：设置 → 显示与阅读 → 锁屏壁纸，只列 TF 卡 `wallpapers/` 里的 JPG/PNG（单张不超过 2 MB）。点一张先做全屏缓存并预览，
  再选“设为壁纸”。缓存是 684×1216 的 16 级灰度（Floyd–Steinberg 抖动），在 `.treader/wall/`。
  原图先被解码器限制在 648×1000 以内再放大，所以大图会略软。锁屏时壁纸铺满，底部白条写在读的书、进度和电量；
  缓存丢了（比如换卡）会在屏幕上电前重建。路径存在 NVS，图片被删就退回书卡。
  预览底栏还有“删除”：点一下变成“确认删除”，再点才删掉卡上这张图；删的是当前壁纸就改回书卡样式。
- **存为壁纸**：小红书、微博看大图时点图片中间或长按图片，弹出“存为壁纸 / 存并设为锁屏”工具条（`main/apps/tr_wallsave.c`），
  把这张图复制到 `wallpapers/`（`tr_lock_wallpaper_save()`），文件名“来源_作者_第几张.jpg”，重名加“(2)”这样的序号，
  同名同大小算已经存过。复制的是服务器处理好的灰度 JPEG（宽 648 以内），做壁纸时稍微放大并居中裁切。
- **书和图片只放 TF 卡**：系统 flash 只放固件、设置和阅读进度（NVS）。官方固件没卡时会把书放进内置 5 MB 的 storage
  分区，Treader 去掉了这个分区（空间给了两个程序槽）：没卡时书库提示插卡，传书页不开始传。书库的筛选改成 全部 / 番茄 / 其他书。
- **TF 卡管理**：设置 → 电源与设备 → TF 卡。格式化要先点“清空并格式化”，再点一次“再点一次确认”；同步进行中不允许。
  格式化前切回内置字体、释放封面缓存和词库，格式化后建好 `books comics fonts ime wallpapers tomato update` 并写一份 `README.txt`，
  清掉壁纸设置。字体和词库要从电脑重新复制。
- **拔卡和换卡**：
  - 拔卡时主循环通知当前页收尾（书库关书、传书停服务、番茄页停同步），取消后台同步，字体切回内置。
    之后读卡的地方都按“文件不存在”处理：封面画文字封面，锁屏用书卡，番茄页提示失败。
  - 卡重新插上（或开机后才插卡）时，等后台同步结束，自动重新挂载；挂好后重载词库、清封面缓存、当前页重新进入一次，
    卡上的字体由定期重试恢复。坏卡或没格式化的卡挂载失败后不会反复重试，拔出再插或到设置 → 电源与设备 → TF 卡处理。
  - 这些都只做了代码检查，**还没在真机上拔插测试**。
- **缓存不越积越多**：删书时同时删它的封面缩略图（`.treader/covers/`）；番茄书还会删下载时存的封面原图。
  离开壁纸页时只保留当前壁纸的全屏缓存，预览过没选的都删掉。书城换榜单日期时清掉旧分类缓存和详情页封面。
  删除是真删除（FAT 没有回收站），阅读进度一起清掉。下载服务器那边的文件库不会被设备清理，需要时在它的 Web UI 里删。
- **阅读排版**：工具条的“排版”（原“清残影”，整屏刷新改用长按中键）打开面板：行距 紧凑 / 标准 / 宽松（字号的 1.3 / 1.5 / 1.8 倍），
  段距 无 / 小 / 大（行高的 0、1/3、2/3，标题固定半行），页边距 窄 / 中 / 宽（24 / 40 / 64 px），首行缩进 按原文 / 缩进两字
  （去掉段首半角、全角和不换行空格，统一空两个“中”字宽，标题和空行不缩进），下划线 无 / 有（每行字下方、行间空白中间一条灰虚线）。
  样式打包成一个字节存 NVS（`bk_style`），默认就是原来的排版。`book_layout_set_style` 统一给分页、绘制和图片命中用，
  改了立即按当前页首的字节位置重排，失败退回原样式。
- **翻页区域**：设置 → 显示与阅读 → 翻页区域，三选一（NVS `turn_zone`，默认 0）：左右（左 3/10 上一页、右 3/10 下一页、
  中间开关工具条，就是原来的行为）；中下翻页（屏幕上 1/4 开关工具条，下面左 3/10 上一页、其余下一页）；点哪都翻（上 1/4 开关工具条，
  其余都是下一页，上一页用右滑或左键）。后两种在工具条开着时点正文只收起工具条，不翻页。点到插图仍先打开插图；左右滑、长按进目录、
  三个按键都不受影响。只管书籍阅读，漫画照旧。选项页每项左边画一块小屏示意（浅灰上一页、深灰下一页、白色工具条）。
- **上一章 / 下一章**：工具条开着时，页脚进度条两边是“‹ 上一章”“下一章 ›”，点了跳到那一章开头、收起工具条并保存进度；第一章没有上一章、最后一章没有下一章，按钮变灰不响应。这时页脚占满左右页边距，进度条夹在中间（仍可点进度条跳到大概位置），下面只写“本章 x/y · 全书 z%”（章名已在面板顶行），放不下就缩字号、再放不下只留数字；章节刻度太密时不画。工具条收起后页脚和原来一样。
- **列表只翻页**：书库、目录、番茄书架、搜索结果、书城榜单、壁纸列表都按页显示，点“‹ ›”或滑一下翻一整页，墨水屏不做滚动。
- **首页并入书库**（2026-11-17）：原首页的继续阅读、最近翻过、番茄提示都和书库或番茄页重复，所以去掉首页，底部标签只剩书库、番茄、设置，
  开机进书库。书架顶部常驻“继续阅读”卡片（`book_progress_recent` 里最近一本，搜索时隐藏），代替原来进书库时的续读弹窗；
  有卡片时每页 4 本，没有时也是 4 本，翻页不错位。番茄书有新章节时状态行右侧显示“番茄 N 本有更新 ›”，点了去番茄页。
- **中键（home）**：短按回书库，长按 0.5 秒整屏 GC16 刷新，由主循环在松手或按满时判定（滑出取消）。阅读时短按开关工具条
  （书库页以 KEY2 在松手时收到短按）。书架上短按回第一页，已在第一页就整屏刷新；`holds_pmu` 页（升级、自检）短按只刷新。原官方行为是按下即刷新、阅读时长按开菜单。
- **键盘**：语言键在 全拼 → 九键 → 英文 之间循环，“123”切数字符号。书库搜索默认英文（匹配拼音首字母），番茄搜索默认全拼。

## 系统升级（在线 / TF 卡）

- 分区表（`partitions_16M.csv`）：nvs 0x9000、phy_init 0xE000 不变；ota_0 0x10000 和 ota_1 0x710000 各 7 MB；otadata 0xE10000。
  没有 factory 分区。`sdkconfig.defaults` 打开了 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`。
- 入口：设置 → 电源与设备 → 关于 Treader → “版本”那一行。页面扫描 TF 卡 `update/` 和根目录的 `.bin`（最多 8 个），检查文件头：
  ESP32-S3（chip id 9）、工程名 Read_Pico、大小不超过程序槽。`Read_Pico.bin` 和合并镜像都能用，合并镜像只取 0x10000 之后的主程序。
- 写入在 `on_tick` 里分块做（每次 32 KB，边擦边写），每 5% 局部刷新进度条；`esp_ota_end` 校验通过后切换启动分区并重启。
  本页设了 `holds_pmu` 和 `blocks_idle_sleep`，升级时电源键不锁屏、不自动睡眠。电量低于 30% 且没充电、或后台同步在跑时拒绝开始。
  拔卡会取消升级，当前版本不受影响。
- 回退：`app_main` 在屏幕和触摸都起来、进入主循环前调用 `esp_ota_mark_app_valid_cancel_rollback()`。新固件没走到这一步就复位的话，
  引导程序下次启动会退回旧槽。
- 网页刷机写完程序会把 otadata 擦成全 FF，保证从刚写入的 ota_0 启动（设备之前可能在 ota_1 上跑）。

### 在线升级

页面上半部分是“在线升级”，下半部分是上面的 TF 卡列表。在线升级不改 CI，直接用 CI 已经发布的 `treader-latest`：

- **检查**：后台任务（`tomato_ota.c`，番茄组件的同步任务里）连已保存的 Wi-Fi，读
  `api.github.com/repos/bidabrain/treader-eink/releases/tags/treader-latest`（约 6 KB），取里面 `treader-<版本>-upgrade.bin`
  的大小、下载地址和 `sha256` 摘要。用固定标签而不是“最新发布”，因为仓库里还有安卓 App 的发布。
- **比较**：只有线上版本号比当前大才提示“下载并升级”；一样显示“已是最新”，带一个“重新安装”（装这个版本号的最新构建）；
  当前更新（本地编译）显示“当前版本比线上新”，不给按钮。
- **下载**：先写 TF 卡 `update/<名字>.part`。下载地址会 302 跳到 GitHub 的文件服务器，`Range` 头一起带过去，所以能续传：
  同一次断了自动重试（最多 5 次，每次有进展就重新计数），下次进来按钮变成“继续下载”，从卡上已有的部分接着下。
  开始前检查：分区表支持升级、升级包不比程序槽大、插着卡、卡上空闲不少于“还要下载的字节 + 64 KB”、电量（同上）。
  带内置番茄服务器的本地版本和同版本重装要多确认一次（升级后是公开版，没有内置服务器）。
- **校验**：下完大小和 SHA-256 都对上才把 `.part` 改名成正式文件；对不上就删掉。随后检查文件头（同 TF 卡升级），
  版本号还要和线上一致，然后走上面的写入流程。
- **清理**：线上换了版本，旧版本的 `.part` 在下次检查时删掉。写入前把升级包的名字和 ELF 摘要前 8 字节记进 NVS（`tr_ota`），
  新固件起来、主循环第一次见到卡挂好时，摘要对得上就删掉这个升级包；退回了旧版本则保留。只删在线升级自己起名的文件，
  手放进 `update/` 的不动。
- **前台**：离开本页、锁屏或拔卡都会停下下载，已下的部分留在卡上。浏览类后台任务（虎扑、小红书等）会让路，
  正在下载书或同步时不打断，提示稍后再试。

## 书城

番茄页顶部“书架 / 书城”切换（番茄标签会记住上次停在哪个）。数据来自 FanqieRankTracker 网站，和安卓版书城同源：

- **搜索在书城**：书城页最上面是“搜索书名或作者”搜索栏，点了进番茄搜索页（键盘、最近搜索、结果、详情和以前一样）。从这里进的搜索，在搜索页或结果页返回会回到书城。书架页不再放搜索栏，书单多一行。

- `api/lastest/index.json`（约 6 KB）列出 37 个分类和各自的文件；每个分类一个文件（约 55 KB，20 本）。不取 1 MB 的 `all.json`。
- **榜单页是 3×3 封面网格**，每页 9 本（一个分类 20 本，共 3 页），封面上不叠字：下面第一行是“名次 书名”，第二行是在读人数，已在书架的书第二行改成加粗的“已在书架”。
  点“‹ ›”或左右 / 上下滑一下翻一整页，不滚动。
- **联网时机**：点“刷新”取分类列表；打开没缓存的分类时取这个分类；打开分类时在后台一次联网取完这个分类缺的封面
  （约 20 张，一般十几秒，期间页面先显示文字封面）；点“下载到书库”下载。取封面让路给用户操作：这时点刷新、换分类或下载，
  会先取消取封面再做。取到的内容缓存在 TF 卡 `tomato/store/`，之后打开直接显示。
- **显示速度**：封面到了以后，本页 9 张缩略图在主循环里逐张生成（每张约零点几秒），全部生成完整页刷新一次，不会一张一张地闪。
  以后再看同一页只读缩略图缓存，翻页基本和文字列表一样快。
- **缓存上限**：封面原图和缩略图都放在 `tomato/store/covers/`。榜单日期变了整个清掉；文件超过 240 个（约 6 个分类）时，
  下次取封面前只留当前分类的。
- 榜单里的番茄链接带 `book_id`，所以详情页可以直接下载（走番茄服务器，和搜索结果的下载同一条路），不用再搜一次。
  详情页取过的封面在下载时直接复制，不重复下载。
- **榜单地址**：`local.properties` 里 `STORE_URL=` 设编译默认（不写就是 `https://bidabrain.github.io/FanqieRankTracker`）；
  设置 → 书城榜单 可以改成自定义地址，留空恢复默认，存在 `config.json` 的 `store_url`。填安卓版那种 `.../api/lastest/all.json`
  也可以，会自动截到网站根。这个地址不是秘密，固件里明文保存，界面正常显示。
- **镜像**：国内直连 `*.github.io` 常超时。榜单地址是 `https://用户.github.io/仓库` 时，失败后依次改用
  `https://{fastly,gcore,cdn}.jsdelivr.net/gh/用户/仓库@main`（仓库 main 分支里提交的 `api/lastest/`），用通的那个记到重启。
  jsDelivr 对分支内容最多缓存 12 小时，所以经镜像看到的榜单可能晚半天。
- 不做安卓版的轮播横幅和随机抽 10 本。

## 漫画

底部第二个标签（`main/apps/app_comic.c`，数据在 `main/book/comic_store.c`），和书库分开管理。界面见 [design/ui.html](design/ui.html) 的“漫画”和“Wi-Fi 传书”“USB 传书”几节。

- **放在哪**：TF 卡 `comics/`。子文件夹是一部系列（只认一层），里面的 CBZ 按文件名自然排序（`第2话` 在 `第10话` 前面）；直接放在 `comics/` 下的 CBZ 是单本。别的文件和更深的文件夹都忽略。
- **上传**：传书网页的“上传漫画”。浏览器解开 CBZ（存储或 Deflate 压缩；文件名 UTF-8 或 GBK），每张图（JPEG、PNG、WebP、GIF、BMP、AVIF，看浏览器支持）转灰度、缩到不超过 648×1000，存成 JPEG（质量 0.85）；高宽比超过屏幕 1.5 倍的长图按屏幕比例切成几张。再按 `0001.jpg` 起的顺序打成不压缩的 ZIP，保留 `ComicInfo.xml`，`PUT /comics?name=…&series=…` 逐个上传。一边转下一话一边传上一话。选文件夹时系列名默认用文件夹名。
- **阅读**：一屏一页，整页缩放居中（区域 684×1160），Bayer 抖动成 16 级灰度。屏幕左右三分之一、左右滑和左右键翻页，中间或中键开工具条。停在一页时在主循环里预解码下一页。翻页用页面模式刷新，每 8 页整屏刷新一次。
- **方向**：默认从左往右；`ComicInfo.xml` 里有 `YesAndRightToLeft` 就从右往左。工具条里切换后按系列或单本记住。
- **进度**：`comics/.treader/progress.txt`，一行一条（页、总页数、最近顺序号、标志、路径），最多 2000 条，满了挤掉最久没看的。每翻 10 页、换话、离开页面时写卡。锁屏或切页回来接着同一页。看到最后一页算看完。
- **封面**：第一张图（系列取第一话），缩成 150×200 存到 `comics/.treader/covers/`，内存里最多 12 张；书架一次生成一张，看得见的都齐了整页刷新一次。
- **限制**：设备只解 JPEG / PNG，单张图原文件不超过 8 MB（大于 2 MB 时还要 PSRAM 放得下），解出来不超过 648×1000。PNG 和基线 JPEG 多大都能边解边缩；渐进式 JPEG 按剩余内存最多约 1～1.6 百万像素。网页转换过的都满足；自己拷进来的 CBZ 里有 WebP 或超大的渐进式 JPEG 时，那几页会提示用网页重新上传。没有“适应宽度”，长条漫画靠上传时切屏。

### WEBTOON 发现与追更

设置了漫画服务器（设置 → 内容来源 → 漫画）才出现。设备**不直接访问 webtoons.com**，只连你自己部署的 [webtoon 服务器](../webtoon/README.md)：服务器读网页上公开免费的话，把一话的竖长条缩到 648 宽、转灰度、在分镜之间的空白处按 1000 高切页，打包成基线 JPEG 的 CBZ。发现页页 `main/apps/app_tr_wt.c`，数据层 `components/tomato/tomato_webtoon.c`。

- **发现页**：我的漫画右上角“发现”。搜索栏（拼音键盘，简体会在服务器上转成繁体去搜），分段 排行 / 类型 / 星期 / 完结，分段下面一到两排二级选项（趋势、人气、原创；各个类型；周一到周日），放不下的点“更多 ›”翻页；下面 3 列封面网格按页翻。封面是服务器转好的 150×200 灰度图。点“刷新”、切到没缓存的分段、搜索、打开详情时才联网；上次的列表存在 `webtoon/store.json`，进页不联网。
- **插件来源**：服务器开了 [插件来源](../webtoon/README.md#插件来源可选)（Mihon 插件）时，搜索栏右边多一个来源按钮，点开“选择来源”列表选 WEBTOON 或某个插件来源，选择存在 NVS（`webtoon` 命名空间的 `src`）。插件来源的分段是 人气 / 最新（来源不支持最新时只有人气），没有二级选项；搜索只搜当前来源，原样发给服务器，不做简繁转换。来源列表跟着发现页列表一起取（`webtoon/sources.json`），换来源本身不联网；服务器是旧版本、没有开插件或只剩 WEBTOON 时不显示来源按钮，界面和以前一样；选中的来源在服务器上没了就回到 WEBTOON。插件作品的编号以 `m` 开头，标记里的语言写 `mihon`，详情封面角上写来源名、话数不写“免费”；订阅、检查更新、补全和我的漫画里的处理和 WEBTOON 一样（也标“WT”、归在 WEBTOON 筛选里）。
- **详情与订阅**：封面、作者、类型、免费话数、简介。没订阅时三个按钮：从第 1 话（起点 0）、只追新的（起点是最新一话，现在不下载）、最近 5 话（起点最新减 5）。订阅就是在 `comics/<作品名>/` 写一个 `.webtoon` 标记（JSON：id、语言、名字、作者、已下载到第几话 `last`、新下载没看的话数 `fresh`、订阅时间），重名的本地文件夹不碰，另起名“(WEBTOON)”。订阅后马上在后台检查一次。已订阅的显示“下载到第 N 话”，可以检查这部的更新、去我的漫画、取消订阅（连点两次；只删标记，一话没下的空文件夹顺手删掉）。
- **检查更新**：我的漫画里的“检查更新”或详情里的按钮。设备把所有标记（或这一部）的 id 和 `last` 一次 POST 给服务器，服务器回比 `last` 新的免费话；逐话问服务器转好没有（每 2.5 秒问一次，一话最多等 6 分钟），转好就下载成 `第0012话 标题.cbz`（先写 `.part`），每下好一话就更新标记里的 `fresh`；全部下完再推进 `last`，只推进到第一个没下好的话（失败、取消、超上限）前面，所以失败的话下次检查更新会自动重下，卡上已有的话跳过。一次最多下几话在设置里选（5 / 10 / 20 / 50，默认 10），剩下的下次再下。下载在后台跑，不让给别的页；我的漫画里的按钮显示“更新中 3/10”，新下好的话马上进我的漫画，结束时状态行写结果（下载了几话、失败的原因）。
- **补全缺的话**：长按订阅的系列 → 详情里“补全缺的话”：按服务器的免费话列表，把卡上没有的（包括订阅起点之前的和自己删掉的）从旧到新下，同样受每次上限限制。
- **我的漫画里**：排序胶囊旁边的来源胶囊在 全部 / 本地 / WEBTOON 之间切换（有服务器或有订阅时才出现）。订阅的系列封面优先用发现页封面，左上角黑底白字“WT”；有新话写“N 话新”（加粗），还没下载到话写“还没下载”或“下载中…”。打开系列时把 `fresh` 清零（后台正在下载时先不改标记）。长按订阅的系列：检查这部的更新、补全缺的话、清除进度、取消订阅、删除。阅读、进度、方向和本地漫画完全一样。
- **设置**：设置 → 内容来源 → 漫画，和小红书那页一样有手机网页填写、服务器地址、设备令牌、测试连接；没有列表条数，换成语言版本（繁体中文 / English，点一下切换）、简体显示（中文版的作品名和简介转成简体，图里的字不变）、每次最多下载。存在 NVS 命名空间 `webtoon`，请求头 `X-Webtoon-Token`。
- **缓存**：`webtoon/`（列表、搜索、详情、封面）可以随时删；下载的话在 `comics/` 里，和本地漫画一起管理。
- **测试**：服务器离线测试见 webtoon/README.md；页面 `tools/page_render/run.sh wt comic settings`。

## 显示大小

设置 → 显示与阅读 → 显示大小，点一下在正常（100%）、大（115%）、特大（130%）之间切换，马上整屏重画。和安卓的“显示大小”一样，界面上的字号、行高、图标、按钮、间距都按比例放大；左右页边距和细线不放大，留给内容的宽度不变。存在 NVS 的 `disp_size`（0 / 1 / 2）。

- 放大后一屏放不下的列表每页少几行，翻页照旧；固定的界面文字和图标都完整显示，书名、帖子、评论这类内容文字和以前一样可能截断。
- 底部标签栏正常 6 格、大 5 格、特大 4 格（含书库和“全部”）；放不下的常用功能这一档只在“全部”里，换回小的档位又回到底部。
- 不放大：阅读正文（字号在阅读工具条里单独设）、漫画页面、看图时的图片、壁纸。

## 时间与时区

设置 → 电源与设备 → 时间与时区（`main/app/tr_time.c`，设置存 NVS `time_auto`、`tz`）。

- **自动校时**：默认开。设备每次联网（番茄、小红书、微博、X、WebDAV、传书等）顺便向 `ntp.aliyun.com` 对时，最多等 3 秒，对上后写进 PMU 的 RTC。SNTP 给的是 UTC，跟时区无关；关掉后联网不再对时（`tomato_net_set_sntp(false)`），只用手动设置的时间。
- **时区**：默认“北京、上海 UTC+8”，可选香港台北、东京首尔、新加坡、曼谷、新德里、迪拜、莫斯科、柏林巴黎、伦敦、UTC、纽约、芝加哥、洛杉矶、悉尼，共 15 个。存的是 POSIX TZ 串，欧美和悉尼按各自规则自动切夏令时。改时区只改显示，内部时间不变。
- **手动设置时间**：自动校时关着时才能点。年、月、日、时、分五栏各有加减按钮，按当前时区的本地时间填写，保存后立刻生效并写进 RTC。
- **开机**：主循环开始时先按设置生效时区，系统时间还没设过就从 PMU 的 RTC 读回（深睡、关机醒来都是重新开机）。从没对过时、也没手动设过时，状态栏不显示时间。

## 自动锁屏与锁屏密码

- **浅睡按键唤醒**：电源键经 PMU 叫醒主机（PMU 记事件并拉低 CW_INT → IO 扩展器中断 → ESP 醒来用 I2C 确认）。CW_INT 是电平，只要有没 ACK 的事件就一直低；以前醒来那一下 I2C 没读到时事件留在 PMU 里，扩展器不再报中断，之后按键都叫不醒（拿起唤醒走加速度计自己的引脚，不受影响）。现在醒来后读 PMU 失败会重试，睡前和每次确认后都把事件 ACK 干净；清不干净（或读不到 PMU）时打开每 1.5 秒一次的定时检查，直接读按键状态，清干净就关掉，平时不多耗电。`main/sleep.c` 的日志写明每次醒来的原因和 PMU 状态。万一还是叫不醒：按住电源键 10 秒由 PMU 强制断电，再长按约 1 秒开机。
- **自动锁屏**：设置 → 电源与设备 → 自动锁屏，点一下换一档：1、2、5、10 分钟或从不，默认 2 分钟（NVS `lock_idle`）。触摸和按键都算操作；后台同步、定时自动翻页、传书页照旧不计空闲。锁屏后浅睡、深睡还是关机仍按“睡眠与锁屏”的档位。
- **锁屏密码**：设置 → 电源与设备 → 锁屏密码，默认关。关着时点它输两遍 4 位数字开启；开着时点它输当前密码关闭（要换密码就先关再开）。NVS 只存 8 字节随机盐加 SHA-256（`pin_hash`），不存数字。
- **什么时候要输**：开机，以及每次从锁屏回来（电源键或拿起唤醒）。深睡和关机醒来本来就是重新开机，同样要输。密码页由 `main/apps/tr_pin.c` 自己画、自己读触摸，主循环在开机进页之前和 `lock_and_resume()` 回页之前调用 `tr_pin_gate()`，过关前任何页面、三键和菜单都不响应。30 秒不操作或按电源键回到锁屏睡眠。
- **输错**：前 5 次直接重输（提示还能试几次）；之后每次先锁定 30 秒，每多错一次多 30 秒，最长 5 分钟；次数重启清零。
- **换 TF 卡不能绕过**：密码在设备内部 flash 的 NVS 里，跟 TF 卡无关；TF 卡升级只能在解锁后的“关于 → 升级”里点。注意 TF 卡本身不加密，拔下来书和缓存照样能在电脑上看。
- **忘了密码**：设备上没有绕过的办法。用数据线连电脑擦掉 NVS 分区（会清空所有设置、阅读进度、服务器地址和 Wi-Fi，固件和 TF 卡不受影响，阅读进度可以从 WebDAV 恢复）：`python -m esptool --chip esp32s3 erase-region 0x9000 0x5000`。同理，能连电脑重刷的人也能这样清掉密码，所以它防的是随手拿起来看，不防有工具的人。

## USB 传书

设置 → 传书 → USB 传书（书库右上角的传书按钮也先到“传书”这一页）。页面 `main/apps/app_usb.c`，U 盘部分 `components/read_pico_usb`（esp_tinyusb 的 MSC），卡的交接在 `read_pico_sd_take_for_usb()`。

- **开始**：后台在下载或同步时不允许（浏览类任务直接取消）。换成内置字体，放下封面缓存和词库，卸掉 TF 卡的文件系统，只初始化卡本身交给 USB。从这一刻起 USB 口是 U 盘，不再是调试串口；TF 卡的挂载、重挂、格式化一律拒绝，直到重启。
- **传输中**：只有这一页。页面接管三键（中键不回书库、KEY3 不开菜单）、占着 PMU（电源键不锁屏、不自动睡眠），没有标签栏。每秒显示电脑写入和读取了多少（链接器包住 `sdmmc_read_sectors` / `sdmmc_write_sectors` 计数）和连接状态：等待连接 / 已连接 / 电脑已弹出 / 已断开。电脑“弹出”时 esp_tinyusb 把卡挂回本机（`/usbmsc`，设备不用），据此认出弹出。
- **结束**：点“结束传输”。电脑还没弹出时先确认。拔线 3 秒后自动结束（用电源芯片的充电状态区分拔线和电脑睡眠：电脑睡眠或让 U 盘省电挂起时还有电，只提示、不结束）。结束一律重启（约 5 秒），开机回到书库，书库、漫画按新文件重新扫描，字体换回设置里的。
- **电脑上**：出现一个可移动磁盘（设备名 ReadPico Read Pico TF，卷标是 TF 卡自己的）。芯片 USB 是全速，实际约 0.8～1 MB/s。
- **刷机**：平时 USB 口是调试串口，插线照常用 `idf.py flash` 或网页刷机工具；只有在设备上点了“开始”才变成 U 盘，插线本身不会切换。USB 传书期间要刷机，先在设备上点“结束传输”等它重启。设备卡死时按复位或长按电源键关机再开，回到串口模式。

## 底部标签

底部标签栏 = 书库（固定第一格）+ 放在底部的常用功能 + 固定最后一格“全部”，一共 6 格（以后的显示大小“大 / 特大”是 5 / 4 格）。所有没隐藏的功能都在“全部”页（`main/apps/app_tr_all.c`）：三列大图标网格，一页放不下就翻页（左右滑或 KEY1 / KEY3）；打开前所在的功能标成选中，进页时停在它那一页，在最后一页按 KEY3 回到那里，中键回书库。底部最后一格、KEY3、阅读和漫画工具条的“菜单”、没有标签栏的老页面右下角把手都打开这一页（原来单独的 KEY3 列表菜单去掉了，弹出的时机不变）。当前页不在底部时，“全部”那一格是选中的。

设置 → 底部标签分三段：
- **放在底部（按顺序）**：第一行书库，固定；常用功能每行有 ↑ ↓ 排顺序、“移出”放回“全部”。
- **只在“全部”里**：“放到底部”（底部满了是灰的，点了提示“底部满了，先移出一个”）、“隐藏”（设置不能隐藏）。
- **已隐藏（“全部”里也不显示）**：“显示”。隐藏的功能入口关闭，缓存和设置不动。

每次改动马上保存并整页重画。常用存在 NVS 的 `tab_pins`（`[个数, 功能号…]`，可以是 0 个）；没存过时按升级前底栏显示的标签（书库、设置以外）原样迁移，设置固定在“全部”里；放不下的（默认是微博）留在表里，只在“全部”里显示（设置页那一行写“这一档在‘全部’里”）。隐藏仍存在 `tabs_off`（按 `tr_tab_t` 位号的掩码），X 默认隐藏（见下文 X 一节）；升级前打开过“隐藏虎扑”（`hide_hupu`）的，第一次启动换算成只隐藏虎扑。隐藏掩码在功能超过 8 个后加宽成 16 位，存在 `tabs_off16`（第一次读时从旧的 `tabs_off` 换算，低 8 位照旧写回 `tabs_off`，降级回旧固件还认得）；功能号最多 16 个。

## 小红书（只读）

底部第四个标签（`main/apps/app_tr_xhs.c`，数据层 `components/tomato/tomato_rednote.c`）。设备**不直接访问小红书**，只连你自己部署的 rednote 服务器（[rednote/README.md](../rednote/README.md)），由服务器登录小红书、拉取并把图片处理成灰度 JPEG。

- **设置**：设置 → 内容来源 → 小红书。地址和设备令牌在 rednote 面板的“设备与外网”页。令牌很长，打开“手机网页填写”：设备连上已保存的 Wi-Fi（没有就开热点），显示二维码和地址，手机打开后粘贴提交；设备保存后停掉网页服务并自动测试连接。网页只收这两项，令牌不回显。也可以点“服务器地址”“设备令牌”用键盘填。存在 NVS 命名空间 `rednote`，不写 TF 卡。在外面用 Cloudflare 隧道时地址填 `https://域名`，HTTPS 和番茄一样用完整证书包。
- **列表**：两列封面卡片，每页 2×2 共四篇，按页翻；封面铺满裁切，下面是标题两行、作者和赞，没看过的标“新”。安卓 App 是同样的卡片，排成上下滑动的瀑布流、封面按原图比例。
- **翻页**：看完一篇返回列表时停在原来那一页；双击顶部当前分段（关注 / 推荐）回到第一页（最新的）。
- **关注**：服务器定时拉好的关注博主笔记。点“刷新”只问自己的服务器（`/api/device/v1/feed`，最近 100 / 200 / 300 篇，按“列表条数”），然后补缩略图。新到的标“新”，点开后去掉。
- **推荐**：点“刷新推荐”时服务器才去读一次小红书首页（视频已滤掉），次数、间隔、缓存时间由服务器面板控制，状态行显示今天还剩几次。第一次切到推荐只取服务器上已有的列表。点开没下载过的推荐笔记时，服务器现拉（约 10～20 秒），设备弹等待框，点框外取消（服务器照样会存好）。
- **看笔记**：先看图，一屏一张（服务器已缩到宽 648 以内、长图切屏），左右点或滑动翻图，最后一张再往后是正文；顶部“图片 / 正文 / 评论”切换。评论是服务器存的前 20 条；评论最后一页末尾有“加载更多评论”，点了服务器现拉这篇最多 60 条（`/note/{id}/more_comments`，先开始再反复问，每次最多等 20 秒，避开 Cloudflare 约 100 秒的超时），设备弹等待框，点框外取消（服务器照样会存好），拉完重读这篇、停在评论页。按钮在设备上判断：评论总数不比显示的多、或者这篇已经加载过（`note.json` 里的 `more_done`）时是灰的，点了没反应，所以升级前缓存的笔记也能用。服务器升级前拉的笔记没有令牌，点了会弹框说明，等服务器下一轮拉取博主时补上。图片在后台一张张下载，正在看的那张一到就显示。
- **缓存**：TF 卡 `rednote/`：`feed.json`、`rec.json`、`n/<笔记>/`（`note.json`、`t.jpg` 缩略图、`1.jpg…` 大图和灰度缓存 `.g`）、`rc/` 推荐封面。两道上限：笔记目录超过 80 个时先删不在两个列表里的旧笔记；目录总大小超过 200 MB 时从最旧的开始删大图（正文和缩略图保留，再打开会补下）。推荐封面只留当前列表的。整个 `rednote/` 可以随时删。
- **内存**：列表、正文行、评论的缓冲进页时在 PSRAM 分配（列表最多 300 篇，约 80 KB），笔记正文按文件大小分配，离页全部释放；图片内存缓存和虎扑共用 `hupu_img`（最多 2 MB），离页释放。后台任务的响应读进 PSRAM（JSON 最多 1 MB，图片最多 2 MB），写盘后立刻释放。
- **只读**：不点赞、不评论、不收藏。没设置服务器时页面只显示说明和“去设置”。

## 微博（只读）

底部第六个标签（`main/apps/app_tr_weibo.c`，数据层 `components/tomato/tomato_weibo.c`）。设备**不直接访问微博**，只连你自己部署的 weibo 服务器（[weibo/README.md](../weibo/README.md)）。服务器不登录，用访客身份定时拉关注的人和热门，带视频的不收，长微博补全文，图片处理成灰度 JPEG。

- **设置**：设置 → 内容来源 → 微博，和小红书那页一样（手机网页填写、服务器地址、设备令牌、测试连接）。存在 NVS 命名空间 `weibo`，不写 TF 卡。两页共用 `components/tomato/tomato_selfhost.c` 里的地址令牌、带令牌请求和缓存清理。
- **列表**：顶部 关注 / 热门，双击当前分段回到第一页（最新的），看完一条返回时停在原来那一页。一条一张卡片：头像圆（名字首字）、粗体名字、下一行时间和来源，正文最多三行，转发的原文在浅灰引用框里，图片在正文下面（两张以上排一排最多三张 164 高的方形小图、多的写“+N”；一张时放大成宽 300），底部转发、评论、赞三栏带图标。每页按卡片高度装满，放不下的整张挪到下一页。关注列表新到的头像右上角一个黑点，点开后去掉；热门不标。点“刷新”只问自己的服务器（`/api/device/v1/feed?seg=follow|hot`，最近 100 / 200 / 300 条，按“列表条数”，关注和热门共用），然后补小图（服务器 0.1.3 起每张原图有方形小图 `s<k>.jpg`；更早拉的微博只有一张封面）。切到没缓存的分段自动取一次。
- **看微博**：顶部和卡片一样的头像、名字、时间来源，再是“正文 / 图片 / 评论”。正文里转发的原文同样在灰框里；最后一页下面一排小图（最多四张，点哪张就从那张原图的第一页看大图，用服务器给的 `starts`），再是三栏计数。往后翻一条线：正文最后一页 → 图片（一屏一张，底栏“‹ 正文 · k / n · 评论 ›”）→ 评论，往前反过来。评论每条带小头像圆。没缓存的微博点开时弹等待框取全文（服务器本地有，很快）。
- **评论**：第一次切到评论时服务器才去微博取一次热评前 20 条并存下，设备存成 `c.json`，以后都用缓存。表情显示成“[笑cry]”这样的文字，只发图的评论写“[图片]”。
- **缓存**：TF 卡 `weibo/`：`follow.json`、`hot.json`、`p/<id>/`（`post.json`、`c.json`、`t.jpg` 缩略图、`1.jpg…` 大图和灰度缓存 `.g`）。两道上限：微博目录超过 150 个时先删不在两个列表里的旧微博；总大小超过 200 MB 时从最旧的开始删大图（`.json` 和缩略图保留）。整个 `weibo/` 可以随时删。
- **内存**：列表（最多 300 条，约 270 KB）、正文行、评论的缓冲进页时在 PSRAM 分配，正文和评论按文件大小分配，离页全部释放；图片内存缓存和虎扑、小红书共用 `hupu_img`。
- **只读**：不点赞、不评论、不转发。没设置服务器时页面只显示说明和“去设置”。

## X（只读）

排在微博后面的标签（`main/apps/app_tr_x.c`，数据层 `components/tomato/tomato_x.c`），**默认隐藏**：新刷的设备和升级上来的设备都不显示，要在设置 → 底部标签里打开（NVS 的 `tabs_x` 记着已经迁移过；以后再存标签设置时一起写上，所以打开后重启不会又被关掉）。设备**不直接访问 X**，只连你自己部署的 x 服务器（[x/README.md](../x/README.md)）。服务器上的浏览器登录你的 X 账号，按随机间隔和睡眠时段拉取，去广告，图片处理成灰度 JPEG。

- **设置**：设置 → 内容来源 → X，和微博那页一样（手机网页填写、服务器地址、设备令牌、测试连接、列表条数），存在 NVS 命名空间 `x`，请求头 `X-Hub-Token`。测试连接顺带读服务器的账号状态和“正在关注”开关。
- **列表**：顶部 为你推荐 / 正在关注，卡片和微博一样；名字下面那行是时间、@账号、谁转推、回复谁、视频（服务器给的字段在 `tomato_x.c` 里拼成一行，按 UTF-8 边界截断）。引用的推文在灰框里写成“引用 @某人：…”。正在关注新到的标黑点，为你推荐不标。

- **只读**：不点赞、不回复、不转推。

## 验证器

在设备上离线显示两步验证码（TOTP，RFC 6238），和手机 Google Authenticator 算出的完全一样，不需要任何服务器。页面 `main/apps/app_tr_auth.c`，会话和 NVS 在 `main/app/tr_auth.c`，验证码计算和加密文件在 `components/read_pico_totp`。手机上的 Google Authenticator 请一直保留：设备不做唯一副本，忘了口令只能清空重导。

- **入口**：新功能“验证器”默认不隐藏、不放底部，在“全部”页里；可以在设置 → 底部标签里放到底部。
- **第一次**：点“设置口令”，输两遍验证器口令（至少 8 位，字母和数字都有）。口令只在设备屏幕上输，和开机密码（锁屏密码）分开。
- **加密**：账号表加密后存在 TF 卡 `treader/totp/vault.bin`（AES-256-GCM）。钥匙 = HKDF-SHA256(PBKDF2-HMAC-SHA256(口令, 随机盐, 迭代次数), 设备随机数)。设备随机数 32 字节，第一次设口令时用硬件熵源生成，存在普通 NVS（命名空间 `totp`）。迭代次数第一次设口令时按设备速度定成解锁约 1 秒（至少 10 万次），写在文件头里。不动 eFuse，不开 flash 加密或 NVS 加密。只拿到卡解不开（没有设备随机数）；只拿到设备拿不到账号（账号在卡上）；设备和卡一起丢，要拆机读 flash 再离线猜口令。写文件先写 `.tmp`，旧文件改成 `.bak` 再改名，断电不会写坏；读的时候按 正式 → `.tmp` → `.bak` 找第一个解得开的。换口令后删掉 `.bak`，旧口令什么都解不开。
- **上锁**：解锁后钥匙和账号表只在内存里。每次锁屏（包括浅睡）、重启、拔卡、开始 USB 传书、点标题栏的锁都会上锁并清零；设置里选了“离开验证器 5 分钟后”时，离开超过 5 分钟也上锁。口令输错 4 次以内直接重输，第 5 次起要等 30 秒、1 分钟、2 分钟……最长 15 分钟；次数存在 NVS，重启后等待从头算，不会清零。输错不会自动清空。
- **列表**：每行一个账号：发行方 · 名称、大号验证码（6 位写成“123 456”，8 位“1234 5678”）、右边倒计时条；剩 5 秒内旁边小字显示下一个码。一页放几行按显示大小算，左右滑或 KEY1 翻页。倒计时每 5 秒局部快刷一次（只用黑白），换码时整页刷新。点一行单独一屏显示特大号验证码；长按一行（或在单独那屏长按）删除，要再点一次确认。支持 SHA1 / SHA256 / SHA512、6 / 8 位、30 / 60 秒；HOTP（计数器型）不支持。
- **时间**：验证码按 UTC 算，和时区无关。时间从没校准过时不显示验证码，提示连 Wi-Fi 校时或手动设置。每次联网 SNTP 校时都记下这次把时钟改了多少（`tomato_last_time_fix_ms()`），两次校时隔 6 小时以上就算出每天漂多少，存在 NVS 命名空间 `trtime`；没测过时按每天 2 秒估。估计误差 = 上次校准时的误差（联网 0、手动 30 秒）+ 漂移 × 距上次校准的时间。超过 10 秒列表顶部提示“时间可能差约 N 秒，点这里连 Wi-Fi 校时”（点了用已保存的 Wi-Fi 只校一次时，不管自动校时开没开）；超过 25 秒验证码旁边标“可能不准”。
- **导入**：已解锁时点标题栏的“导入”。设备开自己的热点（只用设备热点，不走已有 Wi-Fi），口令每次随机、只允许一台手机连，屏幕上有连接二维码；手机打开 `http://192.168.4.1`（页面 `main/apps/auth_form.html`，内嵌 jsQR 1.4.0）。三种方式：选 Google Authenticator“转移账号 → 导出账号”二维码的照片（安卓 GA 不让截图，用另一部手机拍；网页是 HTTP，浏览器不给直接开摄像头）、粘贴 `otpauth://` 或 `otpauth-migration://` 链接（一行一个）、手动填密钥。网页在浏览器里解析迁移数据（protobuf）、去重，发给设备后**要在设备屏幕上点“导入”才写入**；导入完网页清掉输入。网页上也能给已有账号改名、排序、删除（删除同样要在设备上确认）；网页只拿到名称，密钥不出设备，没有导出功能。离开导入页热点就关。
- **设置**：设置 → 内容来源 → 验证器（这一功能自己的设置，由验证器页画）：修改口令（先输旧口令，再输两遍新口令，重新加密）、自动上锁（锁屏或重启时 / 离开 5 分钟后，点一下切换）、清空验证器（连点两次确认，删卡上文件和 NVS 里的设备随机数、输错次数）。验证器标题栏的“设置”按钮也到这一页。
- **异常**：卡上有文件但设备里没有随机数（设备设置被擦过，或卡是别的设备的）：解不开，只能清空重设。设备里有随机数但卡上没有文件（换了卡）：换回原来的卡，或清空重设。
- **测试**：`tools/run_totp_host_test.sh`（RFC 6238 附录 B 向量、base32、账号表、加密文件读写与各种损坏，用 IDF 自带的 tf-psa-crypto 在电脑上编）；`tools/auth_form_test.mjs`（导入网页的链接和迁移数据解析）；`tools/page_render/run.sh auth`。

## 虎扑（只读）

底部第五个标签。移植安卓版 [hupuX](https://github.com/bidabrain/hupuX) 的浏览部分，界面见 [design/ui.html](design/ui.html) 的“虎扑”一节。
顶部分段 推荐 / 关注 / 比分；还有全部专区、专区帖子、帖子详情和比赛评分。

- **数据**：设备直接用 HTTPS 取虎扑移动版页面，不需要自建服务器、不登录、不带 Cookie。
  首页 `m.hupu.com/` 和帖子 `m.hupu.com/bbs/{tid}.html` 都从页面里的 `__NEXT_DATA__` 取（字段路径照 hupuX 的 `doc/api/mobile-api.md`）：
  推荐列表 `props.pageProps.res[]`（`tid`、`title`、`label` 专区、`replies`、`source[]` 缩略图）；帖子 `threadData.data.moduleConfigList`
  （`title`、`user`、`content.moduleContent.content` 正文 HTML）、`initialRepliesData.lightReplies` / `initialReplies`（亮了和前 20 条回复）。
- **后台任务**：和番茄同步共用 `components/tomato` 的同步任务（`tomato_hupu.c`），不会两个同时联网。页面打开要 2～4 秒连 Wi-Fi。
  第 1 步把精简 JSON 写进 TF 卡（`hupu/home.json`、`hupu/post/<tid>.json`），进度到 1 时页面先显示文字；之后下载图片。
- **显示图片开关**：设置 → 内容来源 → 虎扑 → 显示图片，**默认关**（NVS `hupu_img`，开机时交给 `tomato_hupu_set_images()`）。关着时只取文字：列表不带缩略图，正文里的图写成一行“[图片]”，不下载也不解码；已经下好的图留在卡上。打开时先弹提醒：加载图片会大大增加设备负担，可能变慢甚至卡死。
- **图片**：虎扑图床支持阿里云 OSS 参数，统一要 JPG（缩略图 300 宽、正文 600 宽，设备解不了 WEBP）。动图取静态的 `src`。
  `main/book/hupu_img.c` 在页面 on_tick 里一次解一张，缩放成显示尺寸存成 `<图名>_<宽>x<高>.g`，绘制只读缓存、Bayer 抖动；
  本页的图全部做好后整页刷新一次。图片尺寸从文件名里的 `_w_…_h_…_` 读，没下载前就能排好版。
  下载按响应头的长度申请内存（一张几十 KB），不再每张先要 1 MB；没下好的图会说明原因（“有 N 张图没下好（原因），点图重试”），点那张图重新下载。
- **正文**：HTML 转成段落和图片块（引号里的 `>` 不算标签结尾），按 32 px 分页；标题两行内，页首不留段间距。
  视频写成“[视频，请在虎扑 App 观看]”，嵌入卡片（比赛战报之类）写成提示一行。回复里的图写成“[图]”。
- **只在点的时候联网**：点“刷新”取首页；打开没缓存的帖子时取帖子。缓存过的帖子直接打开不联网（不会自动更新回复数）。
  返回列表会取消正在加载的帖子。
- **关注**：关注的专区存在 `hupu/follow.json`（最多 30 个，不用登录）。关注流取前 12 个专区各自第一页（10 条），轮流混排存 `hupu/feed.json`；
  关注变了就删掉旧的关注流，下次进“关注”重新取。全部专区来自 `m.hupu.com/zone`（`props.pageProps.data[].topicList[]`），
  去掉和别的分类重复的“热门”和“站务管理”，按 hupuX 的做法把漏掉的英雄联盟主区（85）补到“游戏”第一个，存 `hupu/zones.json`。
- **专区帖子**：最新回复走 `m.hupu.com/api/v2/bbs/topicThreads`，一次 10 条，翻页要带上一页的 `nextCursor`（不带只会重复第一页）；
  最新发布走桌面版 `bbs.hupu.com/{id}-postdate[-页]` 里的 `window.$$data.topic.threads`，一次 50 条。翻到还没取的一页时取下一批并追加，
  每个专区最多缓存 200 条，存 `hupu/zone/<id>_<排序>.json`，最多留 40 个文件。
- **比分**：赛程接口 `match-api.hupu.com/…/getScheduleListByTagForH5?businessId=`（nba、cba、epl、lol、tennis），一次返回整季约 200 场、
  NBA 约 420 KB。按天存 `hupu/sched_<赛事>.json`，记下“今天”那天（`dateBlock` 以“今天”开头，否则用 `anchorMatchId` 那天）。
  开赛时间按毫秒时间戳加 8 小时显示，不依赖时区。已结束的比赛点进去看评分：赛程给的是条目键，先 `getSelfByBizKey` 找父比赛，
  再 `getCurAndSubNodeByBizKey`（relation=CHILD）取全场条目，存 `hupu/rate/`（最多 20 个）。球员的 `teamId` 等于赛程里的 `memberId`，
  能分开两队就按队显示，按评分从高到低排。
- **缓存上限**：帖子最多 30 个；`hupu/img/` 超过 400 个文件时只留当前用到的图。整个 `hupu/` 可以随时删。
- **内存**：页面的列表、专区、赛程、帖子缓冲进页时在 PSRAM 分配（约 300 KB），离页全部释放；图片内存缓存最多 2 MB，离页释放。
  后台任务把响应读进 PSRAM、解析完立刻释放原文，cJSON 树精简写盘后马上删除。解析前检查 PSRAM 剩余不少于原文 3 倍
  （NBA 赛程解析峰值约 1.5 MB），不够就提示“内存不足”而不是半路失败。
- **不联网**：所有视图都先读 TF 卡缓存。没设置 Wi-Fi、连不上或虎扑取不到时，后台任务失败，页面留一句提示，缓存照常显示；
  没缓存的地方提示“联网后点刷新”。自动联网只发生在打开没缓存的内容时，一次失败后不会反复重试，等用户再点。
- **翻页**：列表、正文、回复都按页；点“‹ ›”、滑一下，正文页还可以点左右两侧。点回复看全文，点图全屏看，左键返回上一层。

## WebDAV 同步

Treader 设备和 WebDAV 服务器之间同步（和以前的 Tomato-Novel 安卓版无关；本仓库的番茄安卓 App 用同一个文件），只在“设置 → 同步 → 立即同步”时运行，用完断网：

- 服务器目录下放一个 `treader-sync.json`，用 GET 读、PUT 写，HTTP Basic 认证。坚果云要用“应用密码”。
- **阅读进度**：TF 卡 `tomato/webdav_state.json` 记着上次同步时每本书的进度签名。本机进度变了就以本机为准上传；
  本机没变、服务器那条在上次同步之后更新过，就以服务器为准写回本机。本机文件不能比记录时小（番茄更新只追加章节）。
- **只在服务器上的进度**：比上次同步新、或者本机从没同步过这本书时写回（先同步、后下载书也能接上）。写回前用 `book_position_fits` 单独打开这本书（不动正在读的书源），章节号或章内偏移超出就不用：文件和备份时不一样（比如换了下载服务器），同步结果里说明有几本。
- **番茄书架**：按 `book_id` 取并集。只在服务器上的书加进本机书架，标成有新章节，点“下载全部更新”即可拉下来。
  每本书的 `seen`（上次打开时的章节数）两边取大：在一边打开过，另一边下载了还没看的“+N 章”也消失。旧版本不认识这个字段，同步时会把它丢掉，只影响跨设备的“已看”，不影响本机。
- **番茄安卓 App**（`tomato/android`）用同一个文件和同样的规则，阅读进度和番茄书架和设备互通。
- 书籍文件本身不传；删除不同步。

### 内置默认服务器

和安卓版一样，可以在编译时把默认番茄服务器打进固件。在项目根目录建 `local.properties`（已在 `.gitignore` 里，不会入库）：

```properties
DOWNLOADER_URL=http://你的服务器:端口
DOWNLOADER_PASSWORD=你的密码
```

也可以用同名环境变量。编译时会打印 `Treader: built-in Tomato server enabled`（不打印值）。规则：

- 设置里填了服务器就用填的；没填（或填写时留空）就用内置的。
- 界面上只显示“内置服务器”，不显示地址和密码；编辑时也不回显。
- 地址和密码在固件里是异或混淆的，`strings` 之类的工具搜不到明文。但这只是混淆不是加密：
  拿到固件的人仍然能逆向出来，和安卓 APK 里的 BuildConfig 一样。**带内置服务器编出的 `.bin` 不要公开发布。**
- 公开仓库的 CI 没有这个文件，编出来的固件不带内置服务器。

Wi-Fi 沿用系统“传书”页里保存的网络，不需要另外设置。

检查更新和下载是两个独立操作，都只在用户点击时运行，**不自动检查**：

- `tomato_sync_start_check()`：只向服务器取最新章节数，写进 `shelf.json` 的 `remote` 字段。
- `tomato_sync_start_update()`：下载 `remote` 大于本地 `chapters` 的书，用的是上次检查的结果。没有待下载的书时不连网。

更新判断沿用安卓版 v1.7.3 的规则：服务器章节数取 `max(remote_total, local_total)`，大于本地章节数才算有更新。

**新章节提示**：书库和番茄书架每本番茄书右边分两种（`tomato_book_pending` / `tomato_book_fresh`）：

- “+N 章 待下载”：检查到、还没下载，N = `remote − chapters`。书库状态行的“番茄 N 本有更新 ›”和“下载全部更新”只看这一种。
- “+N 章”：已经下载、打开后还没看，N = `chapters − seen`。`seen` 是上次打开这本书时的章节数，存在 `shelf.json`；在书库或番茄书架打开（包括继续阅读和开机恢复）成功后、以及退出这本书时记成当前章节数，提示消失。
- 两种都有时显示待下载。第一次下载一本书（新书，或 WebDAV 同步来、本机还没有文件的）下完就算看过，显示“未读”。
- 旧版本写的 `shelf.json` 没有 `seen`，读的时候当作等于 `chapters`：升级前已经下载、没打开过的书不再提示（旧文件里没有下载前的章节数），待下载的照常提示。
- 后台任务开始时读一份书架，期间页面可能记过“已看”，所以 `tomato_shelf_save` 每次都和磁盘上的文件合并 `seen`（取大），旧副本冲不掉。主机测试：`tools/run_tomato_store_host_test.sh`（在 Docker 里跑，会写 `/sdcard/tomato`）。

搜索结果带简介（服务器 `/api/search` 返回的 `abstract`，截到约 100 个汉字），用于书籍详情页；点“下载到书库”才下载。

## 静态检查与已知限制

静态分析构建（GCC `-fanalyzer` 加 `-fstack-usage`，只作用于 Treader 相关代码）：

```bash
idf.py -B build-analyze -DTREADER_ANALYZE=1 build
```

每个函数的栈占用写在 `build-analyze/**/*.su`。目前 Treader 代码没有 analyzer 警告；
后台同步任务栈 14 KB，大缓冲都在 PSRAM 工作区里。大的静态数组用 `EXT_RAM_BSS_ATTR` 放 PSRAM
（`sdkconfig.defaults` 打开了 `CONFIG_SPIRAM_ALLOW_BSS_SEG_EXTERNAL_MEMORY`）。

已知限制：

- 漫画：渐进式 JPEG 只能整张解，每像素约要 5 字节内存，设备按当时剩余 PSRAM 最多解约 1～1.6 百万像素；更大的页显示不了，用传书网页重新上传会自动转换成普通 JPEG。基线 JPEG 和非交错 PNG 边解边缩，不受这个限制。
- 主机回归测试（`tools/run_book_management_tests.sh`）要 gcc 和 zlib，0.4.0、0.4.1 的改动只在固件里编译过，没有实际跑。

为了不出错而定的规则：

- **正在阅读的书不更新**：阅读器还开着旧文件，替换会读到乱码；“下载全部更新”会跳过它并提示。
- **同步期间不自动锁屏**；按电源键锁屏且会断电时，先取消同步并等它停下（最多 8 秒）。
- **书库删书**时若同步正在进行，删除记录排队，等同步结束再处理，免得被写回。
- 删掉的番茄书记在 `tomato/removed.json`，WebDAV 两边合并时不会再加回来。
- **WebDAV**：没对上时不同步；服务器文件读得到但解析失败时不覆盖；某本书在本机从没同步过而服务器有，以服务器为准。
- 文件写入都是“写 .tmp 再改名”，改名失败或掉电时下次读取用 .tmp 恢复。

已知限制（没做）：

- 查询服务器任务状态时每次轮询都重新建立 TLS 连接，没有复用。
- WebDAV 没用 ETag，两台设备同时同步可能丢掉其中一方的这次更新（下次同步会补上）。
- 番茄页进入时会对每本书做一次 `stat` 和 NVS 读取（64 本以内，约百毫秒级）。
- 浅睡锁屏期间换卡，驱动看不到拔出，解锁后仍当成原来那张卡。默认锁屏是关机，不受影响；用浅睡时换卡请先解锁再换。
- 用 esptool 把合并镜像整个写到 0x0 不会重置 otadata；设备上次从 ota_1 启动的话，新写的 ota_0 不会生效。命令行请用 `idf.py flash`。

## 界面代码

| 路径 | 职责 |
| --- | --- |
| `main/ui/tr_ui.c` | 新风格的绘制原语：状态栏、标签栏、文字封面、点线进度条、胶囊按钮、线条图标、自动换行。 |
| `main/ui/tr_kbd.c` | 屏幕键盘：26 键拼音、英文、数字符号，带候选条。 |
| `main/ui/ui_scale.h` | 显示大小：`UI_S()` / `TR_S()` 按 100 / 115 / 130% 换算界面长度。 |
| `tools/page_render/` | 页面渲染测试台：在电脑上用真实页面代码画三档显示大小，检查出屏、压标签栏、文字截断和重叠，并和改动前的代码逐像素比对 100%，用法见 `run.sh`、`compare.sh` 文件头。 |
| `main/app/tr_nav.c` | 标签页切换，以及从别的页面直接打开一本书。 |
| `main/apps/app_tr_tomato.c` | 番茄标签页：书架、检查更新、下载全部更新、搜索、结果、详情。 |
| `main/apps/app_tr_settings.c` | 设置页：番茄服务器、WebDAV 的编辑和“立即同步”；提供进度导出/导入给 WebDAV。 |
| `main/apps/app_book.c` | 官方书库与阅读器，书架和工具条改成新排版，逻辑不变。 |
| `main/apps/tr_lock.c` | 锁屏书卡；没有在读的书时用官方锁屏图。 |

带标签栏的页面在 `app_desc_t` 里设 `.tab_nav = true`，右下角菜单按钮的点击区让给标签栏；KEY3 仍然打开“全部”页。
新增界面文字后要重新生成内置字体子集：`python tools/gen_builtin_font.py`（需要 fonttools）。
